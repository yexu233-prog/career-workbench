# 求职工作台Mac测试版使用说明

本版由Windows组装，提供Apple Silicon（mac-arm64）与Intel（mac-x64）两套ZIP，目标为macOS 14及以上。Apple Silicon 已由用户在 macOS 14 完成自检与人工验收；Intel 包为**实验性、未完成实机验证**。实际验证范围及重建包的参考验收关系见[Mac验收与发布范围](Mac验收与发布范围-20261009.md)。不以组件最低版本推定所有未来macOS均已验证。

## 开始使用

1. 核对ZIP来源及配套SHA-256。终端可运行 `shasum -a 256 ` 后拖入ZIP，与 `.zip.sha256` 内容比较。哈希只检查文件一致性，不代表Apple签名或公证。
2. 使用访达解压到本机普通文件夹，可以有中文和空格。保留整个文件夹。
3. 双击“启动求职工作台.command”。终端先检查文件及权限，再让你选择 `1 Safari` 或 `2 Chrome`；后续可按回车使用上次选择。
4. 浏览器打开 `http://127.0.0.1:41823` 后开始使用。请保留启动终端；关闭网页不会停止本机服务。
5. 完成后双击同一个包里的“停止求职工作台.command”，或在启动终端按Control+C。停止会取消未完成的AI/PDF任务。

Mac端无需安装Node、Git、Homebrew、Xcode或开发工具，不执行npm安装或旧的“制作两套Mac测试包.command”。包内已带匹配架构的Node、钥匙串接口组件、PDF引擎和字体。选择Chrome需要设备本身已安装Chrome；未安装时可在下一次启动选择Safari。

本批没有Developer ID签名或Apple公证。如果系统提示无法确认开发者，在确认文件来源及校验和后，按macOS提供的“隐私与安全性”授权提示操作。若没有允许入口、原生组件不能加载或反复被阻止，保留提示并反馈。不要关闭Gatekeeper/SIP、批量删除隔离属性或安装开发工具处理。

## 数据与AI配置

- Safari与Chrome，以及各浏览器不同用户资料的数据相互独立。切换前在“设置→数据备份与恢复”保存完整备份，再在目标浏览器恢复；目标已有资料时先备份，恢复会替换数据。
- 固定使用 `127.0.0.1:41823`，不要改成localhost或其他端口。数据保存在当前浏览器的IndexedDB，不在ZIP或产品文件夹中。
- API Key通过随包Node保存到当前Mac用户的文件型本机钥匙串。该接口不使用iCloud钥匙串；密钥不会进入业务备份、浏览器数据库、日志或明文配置文件。调用AI时仍会在进程内存中短暂使用密钥。
- macOS可能提示随包“node”访问本应用的钥匙串条目。只确认本应用对应项目；不要将其他钥匙串项目设为允许所有应用访问。程序移动、升级或更换Node后可能重新请求授权。
- 钥匙串锁定、授权拒绝或配置损坏会限制AI，页面会说明；手动功能仍可使用。不会自动改成明文保存。超时可能发生在系统已经保存之后，请重新查看状态后再决定重试。
- Windows与Mac之间通过业务备份迁移资料，API Key需要在Mac重新填写。同一Mac用户的两种浏览器可以使用相同服务端AI配置。
- 启动偏好、受限运行记录位于当前用户 `Library/Application Support/求职工作台`；它们不是业务数据库。删除程序文件夹不会自动删除浏览器资料或钥匙串项目。清除AI配置请使用产品设置页。

## 自检与人工验收

先停止工作台，再双击“运行自检.command”。自检检查包文件、运行时、钥匙串绑定加载、本机页面和字体、虚构内容PDF及停止流程。它不打开用户的浏览器数据库，不读取或覆盖已保存的API Key。

结果保存在当前用户 `Library/Application Support/求职工作台/验收记录`。自检不会改写包内验收状态。报告中的packageId及manifestSha256可与对应ZIP的元数据关联。

自行复核或反馈故障时，可按以下已验收项目检查；Intel 仍待对应实机验证：

1. Safari和Chrome分别启动，完成首次引导、输入虚构资料、刷新并重启，检查保存、回收站、导入、素材版本、照片及简历项目。
2. 使用测试API配置检查钥匙串保存、读取、更新、删除、拒绝/锁定提示；只在设备所有者同意后调整其钥匙串锁定状态。不锁定或清理他人的项目来制造故障。
3. 检查PDF一页、多页、中文/英文、照片、长内容、取消和停止；检查Word的文字编辑、照片、顺序、加粗和手动分页。Word未安装时把该项记为待验收。
4. 用虚构数据进行Safari/Chrome及Windows/Mac完整备份迁移；检查下载后确认、取消保存和失败提示。
5. 检查中文路径、移动包、重复启动、端口占用、关闭终端和重新打开。另一架构必须在对应设备验证，不能用改包名或Rosetta代替验收。

借用电脑仅使用虚构简历、照片和岗位信息。如当前浏览器已有他人的工作台资料，先停止并与设备所有者协商独立用户资料，不覆盖其数据。

## 常见问题

- 提示芯片不匹配：Apple Silicon使用arm64，Intel使用x64。本包不会自动安装Rosetta。
- 提示端口占用或已有启动窗口：使用原目录的停止入口结束旧包，再启动新版；不会自动换端口或结束未知程序。
- 提示文件/权限不完整：重新解压原ZIP，不要从Windows手动复制单个程序文件到Mac。检查是否被同步软件或压缩软件修改。
- 钥匙串无法访问：检查系统授权或本机钥匙串是否已解锁，然后重试；不要在聊天中提供密钥或系统密码。
- PDF失败：确认包未删减、系统允许运行随包引擎，并运行自检。PDF引擎独立于Safari/Chrome，无需安装Edge。
- AI连接失败：核对厂商地址、模型、额度和系统HTTP/HTTPS代理。PAC、SOCKS-only及代理认证尚不支持；不关闭TLS验证。
- 启动终端异常被结束：控制连接断开时服务会尝试退出；若仍占用端口，用原包停止入口。保留提示交回开发机排查，不强杀未知进程。

## 升级与回退

在旧版运行时先保存业务完整备份，再停止旧版；新版解压到独立目录，启动后核对原浏览器、固定地址和资料。保留旧包及升级前备份。当前数据库结构没有因Mac适配升级；后续遇到不兼容版本，按对应发行说明恢复升级前备份，不直接让旧程序写新版数据。

包内 `version.json` 记录平台、架构和验证状态；`manifest.json` 记录文件、权限及链接；`licenses` 保存第三方许可。本次保留标准A4单栏模板和现有PDF/Word导出。
